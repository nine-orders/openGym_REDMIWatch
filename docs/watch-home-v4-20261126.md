# 开炼手表首页 V4 实施记录

## 实施计划

1. 基于当前工作区增量修改。延用 1.0.8 两种手机传输、快照版本控制、电脑配对和已有训练页。
2. 将首页改为 V4 启动台。独立训练读取本地动作单，手机同步经用户主动选择进入等待或续训。已加入的手机会话按训练 ID 固定，换场时结束当前跟记。
3. 让电脑整场记录先落盘再上传。手机事件按训练 ID 汇总，原目标持久化，接收端确认后逐项移除。区分手机持久收件与历史入账，未核实归属的旧数据保留在手表。
4. 接入设置、连接管理、待同步详情及重试。默认休息仅用于独立训练的默认值，动作专属时长优先。手机跟记使用手机休息状态，手表的振动开关只影响本机提醒。
5. 回归独立训练、手机跟记、部分成功、重启恢复、设备切换和 1.0.8 桥接。构建沿用正式签名的 RPK，记录包版本、校验及真机待验收项。

现有手机事件协议负责记入指定活动会话，手机忙于其他训练时不会接纳手表的另一个 `start`。手机动作单供独立训练离线使用时，独立训练数据整场保存在手表，原手机与其历史之间的独立导入需要单独的协议支持。已有电脑动作单继续同步到其原电脑档案。

## 实施结果

- 首页采用黑底 V4 纵向布局和双绿训练卡。当前仓库 `icon.png` 实际为绿色「炼」字。首页及关于页使用配套 OpenGym 手表工程 `watch-app/src/icon.png` 的黄底橙色角色原图，复制为本仓库 `watch-app/src/brand-icon.png`。
- 设备行显示应用层连接结果，使用已存配置自动重试。在设置中可切换连接、改为离线、解除配对、检查系统通道与 HTTP、查看本地存储和版本。休息设置提供跟随动作单、不休息及 30 至 300 秒选项，动作专属时长优先，振动开关影响手表的休息结束提醒。
- 独立训练优先使用手表本地动作单。电脑记录在发送前持久化，保留原训练日期与 ID，原电脑确认后逐场移出。手机跟记由用户主动进入，同场断线可按原会话继续，手机换场后显示原场总结。手机可同步自由训练，休息优先使用手机快照。
- 待同步按训练 ID 汇总，部分确认后仍显示有剩余事件的场次。手机事件队列上限 600 条，540 条触发本地容量提醒。电脑整场存储容量依设备余量，存储失败会保留当前训练并显示提示。1.0.8 的 `acked` 表示手机收件箱已持久收到，界面提示在手机确认训练历史。
- 原电脑档案通过保存的端点与档案 ID 关联。旧配置缺档案 ID 时用原保存连接识别。手机按保存的连接归属，手机旧开场事件仅在快照已明确匹配同场时补传，避免让旧事件创建活动会话。原设备关系无从确认的旧记录保存在手表。小米系统通道未向 1.0.8 手表业务层暴露稳定的实体手机或档案 ID。

## 真机待验收

1. 红米 Watch 5 覆盖更新、原数据保留、首页一屏触控、常见与长状态文案、振动与重启持久化。
2. 配套 1.0.8 安卓端的系统通道与手机 HTTP 配对，锁屏、进程重启、授权或监听重连。验证手机先开练、主动等待后开练、自由训练、改组和结束，以及手机中途换场。
3. 原电脑恢复补传、半个月真实离线及真机容量。复测客户端已接收但历史尚未处理、两端并行训练、部分回执和原设备切换。
4. 手机动作单用于独立训练后，1.0.8 缺少整场导入。更换实体手机或档案后，系统通道旧事件的归属仍需设备实测。
